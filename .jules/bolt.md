## 2025-09-06 - Optimized Submodule Modifying Process
**Learning:** We are strictly not allowed to leave submodules in a dirty state or advance upstream submodule pointers directly when working in a root repository, unless specifically authorized. If a change to a submodule is required, the correct way is to create a patch file and store it in the root repository (e.g. `patches/`), then update the environment setup script (e.g. `jules_setup.sh`) to apply the patch dynamically to the submodule on setup.
**Action:** Always check `git status` after making code changes. If you modified files inside a submodule, you should revert those submodule changes and instead export a diff as a `.patch` file into a `patches/` folder in the main repository, and then add a `patch -p1 < patches/my_patch.patch` step to the project's setup script (`jules_setup.sh`).

## 2025-09-06 - Optimized Python Dictionary Key Comparisons
**Learning:** Generating sets out of Python dictionary keys and doing set unions/intersections on them is extremely inefficient for checking if a list of dictionaries all have identical schema keys. Doing `if item.keys() == first_item.keys()` is dramatically faster because Python dictionaries natively optimize `dict_keys` comparisons and it doesn't instantiate any `set` or `tuple` copies.
**Action:** When verifying if an array of objects has the exact same schema keys, always use the fast path: `if all(isinstance(item, dict) and item.keys() == first_keys for item in arr)`. This reduces O(N) complex set operations down to efficient native `dict_keys` equivalencies.
